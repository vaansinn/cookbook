## Source-grounded risks and test status

- [auth.py:195–237](../../../routes/auth.py#L195) exports only rows associated with the **current** household; leaving deletes membership ([groceries.py:74](../../../routes/groceries.py#L74)), so demonstrably attributable former-household facts may be omitted. A grocery row's `added_by` does **not** prove ownership of every contribution in a merged quantity or source list ([groceries.py:134](../../../routes/groceries.py#L134)); a proposed former-member export must not reveal co-member merged details. Deletion nulls attribution across households but only removes the current household if last member ([auth.py:239](../../../routes/auth.py#L239)); a plain `leave` leaves a last-member household behind. There is no automatic owner transfer in the route. The account deletion has a single commit and the private-planning/user locking path, but representative former-member and shared rollback cases still need tests.
- [models.py:241](../../../models.py#L241) returns member email/display name and invite code to every current member. [groceries.py:60](../../../routes/groceries.py#L60) accepts any valid code and has no expiry, rotation, invitation grant or member removal endpoint. [meal_plans.py:255](../../../routes/meal_plans.py#L255) discloses owner display name and lacks a revoke/expiry endpoint. Hiding UI links does not close these paths.
- [groceries.py:98–162](../../../routes/groceries.py#L98) can commit list creation before validating a recipe and merges quantities by a non-locked read/update. `serves` is used arithmetically without a local type/range check. [groceries.py:214](../../../routes/groceries.py#L214) validates required strings and tier entitlement but does not confirm a dish/tier row; [groceries.py:248](../../../routes/groceries.py#L248) repeats merges on retry, skips unavailable entries and lacks a per-entry tier check. `PATCH` coerces arbitrary `checked` values to boolean ([groceries.py:164](../../../routes/groceries.py#L164)). These are validation/retry/access findings, not claims of an observed exploit.
- [meal_plans.py:124](../../../routes/meal_plans.py#L124) checks current tier before its list merge (covered by T4), while `apply-week` appends entries on each retry ([meal_plans.py:161](../../../routes/meal_plans.py#L161)). Shared public output summarizes named plan items but recipe detail remains separately tier-gated ([recipes.py:60](../../../routes/recipes.py#L60)).
- Private commands have a 16 KiB envelope, revision check, mutation digest/receipt and one commit ([planning.py:115](../../../routes/planning.py#L115), [planning.py:340](../../../routes/planning.py#L340)); catalog reads require a current user and published/eligible content ([planning_catalog.py:316](../../../planning_catalog.py#L316)). This is source evidence, not candidate browser or PostgreSQL acceptance.
- D02's [parity map PX07–PX09](parity-evidence.md) distinguishes private `/planning/*` and `/shopping` from existing frontend `/plans`, `/plans/:shareSlug`, and `/groceries` routes ([App.jsx:67](../../../frontend/src/App.jsx#L67), [App.jsx:79](../../../frontend/src/App.jsx#L79), [App.jsx:95](../../../frontend/src/App.jsx#L95)). These are separate record namespaces; a friendly URL alias may resolve to the same **private** ID, but a legacy ID or public slug must never be guessed into a private workspace. D02's source-level PX08 pre-save preview gap does not change the current server entitlement gate.

**Proposed PX07 disclosure for D10:** a destructive impact preview may show the authenticated owner's exact affected scope IDs and labels, lost source/check amounts, extras and personal item IDs/amounts needed for informed confirmation. Return only affected records from the same workspace, with bounded size and no other member's profile, receipt/inverse payload, unauthorized recipe prose or unrelated selection. [planning_changes.py:133](../../../planning_changes.py#L133) already captures owner-scoped affected scope state and counts, while the rendered dialog currently shows only the counts ([PlanningDialog.jsx:246](../../../frontend/src/components/planning/PlanningDialog.jsx#L246)). Define a minimal redacted loss projection from that state, re-evaluate effects at confirmation, and reject foreign/expired/stale previews without writing ([planning_changes.py:243](../../../planning_changes.py#L243)). Synthetic test: two linked plans with 220 g and 600 g checked sources, 100 g extra and two personal items; preview returns only the exact losses for A, hides B and unaffected A records, and an intervening mutation yields 409 with unchanged rows. This is a proposed contract and test, not current UI behavior.
